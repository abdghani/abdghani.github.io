01 — AI Work

Production AI, built on solid backends

I treat LLMs as one more unreliable dependency: ground them in your data, compute the numbers in code, scope them by permissions, and keep them off the request path. Here's what that looks like in practice.

Delightree · LLM agents · LangChain · LangGraph

AI Analyst — an agent franchise owners can trust

Franchise owners ask questions in plain English, like "Which locations are falling behind on training, and why?", and get verified answers in seconds, with tables, charts and one-click actions. The hard part isn't the chat. It's making sure every number the agent shows is correct.

RouteAn LLM router selects the right tools from a catalog spanning the whole business
→
GatherA ReAct agent calls those tools against live platform data
→
ComputeEvery figure is calculated in code from the shared metric catalog, never guessed by the model
→
AnswerA second model writes a schema-validated answer that is checked before it is shown
  • Two-stage design: the router narrows a large tool catalog down to the few tools a question needs, which keeps the agent fast and focused.
  • Built on the LangChain ecosystem: the router → ReAct → answer flow is orchestrated as a LangGraph graph, with every data source exposed as a typed LangChain tool.
  • Numbers you can trust: results are checked again and rebuilt from the same metric catalog the dashboards use, so chat and dashboards always agree.
  • Structured output: answers follow a schema, so the frontend can show tables, charts and action buttons instead of plain text.
  • From answer to action: answers come with one-click actions, so owners can act on what they find without leaving the chat.

AI Search — cited answers from a company's own knowledge

Franchise teams used to dig through binders, PDF libraries and group chats to answer everyday questions like "What's the refund process for a delivery order?" or "What's the closing temperature for the line?" AI Search is a vector-based RAG engine that answers those questions in plain English, on any device, and shows the source SOP behind every answer so teams can check the original.

IndexSOPs, manuals, training modules, policies, checklists and audits are embedded into a vector index that updates automatically when content changes
→
ScopeRetrieval respects the network's permissions: franchisees only see their brand's content, and multi-brand operators control visibility per brand
→
AnswerThe LLM answers only from the retrieved, approved content and returns the exact answer with its source reference
→
LearnThumbs-up/down feedback and search analytics reveal knowledge gaps and trending topics for HQ
  • Grounded by design: answers come only from content the franchisor has uploaded and approved, so every location gets the same current answer.
  • Multi-tenant safe: retrieval is filtered by the same permission hierarchy as the rest of the platform, so brands never see each other's content.
  • No separate pipeline: it works on content already in Delightree in any format, and edits to the knowledge base reach search automatically.
  • Less load on HQ: locations get answers on their own around the clock, and new hires ramp up without waiting on a manager.

Brifly — give your meetings a memory

Meetings get recorded in Read.ai, Fireflies, Zoom and Microsoft Teams, and follow-ups happen over email, so nothing can be searched in one place. Brifly pulls all of it into one private library and adds an AI layer: ask questions across every meeting, chat with a single meeting, get weekly digests and turn action items into tasks. Every answer cites the exact speaker and timestamp.

IngestRead.ai (OAuth 2.1), Fireflies (GraphQL), Zoom & Teams (OAuth 2.0, VTT parsing), plus read-only Gmail & Outlook
→
QueueBullMQ + Redis workers: embed, enhance-actions, digest
→
IndexOpenAI text-embedding-3-small → Qdrant, with per-meeting and global collections
→
AnswerClaude Haiku 4.5, grounded in retrieved transcript chunks and citing speaker + timestamp
  • LangChain RAG pipeline: transcripts and emails are chunked, embedded and retrieved through LangChain, with Qdrant as the vector store and Claude generating the cited answers.
  • Two RAG modes: scoped retrieval for chatting with one meeting, and global retrieval across all meetings with per-source filters. Conversation history is saved and can be copied, regenerated or downloaded.
  • One schema for every source: four meeting providers with different auth flows and formats are normalised into one model. Split "Conference Room – Speaker 1/2" tracks are merged into one speaker timeline.
  • Action items to tasks: Claude adds priority, assignee and deadline to existing action items, or extracts them from raw transcripts. Tasks are grouped as overdue, today, this week or later.
  • Scheduled AI digests: weekly digests (Mondays at 8 AM in the user's timezone) and monthly ones cover key themes, decisions and the top action items, each linked back to its source meeting.
  • Email intelligence: read-only Gmail and Outlook sync finds the key threads, action items and who's waiting on your reply.
  • Built for production: sync runs sequentially with retry-with-backoff on 429s and concurrency-safe jobs, and LLM and embedding work stays off the request path. Auth uses email/password or Google OAuth, with accounts merged by email.

DriftHost — describe a website, watch it go live

An AI website builder and static hosting in one product. You chat, and the AI streams real HTML, CSS and JS while the live preview updates. You can click any element in the preview and say what to change, or edit the files directly. Every AI turn is checkpointed and can be reverted. Publishing creates an immutable, versioned snapshot on yourname.drifthost.site, served from an edge CDN, and rolling back takes one click. Developers can skip the chat and run drifthost deploy.
